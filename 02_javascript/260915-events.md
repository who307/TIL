## TIL(Today I Learned)

* `addEventListener` 및 `removeEventListener`를 활용한 이벤트 등록과 해제 메커니즘 학습
* `e.target.closest()` 기반 이벤트 위임(Event Delegation)으로 다수의 자식 요소 이벤트를 부모 요소 단 1개에서 일괄 처리하는 패턴 학습
* `e.stopPropagation()`을 이용한 이벤트 버블링 차단 및 모달 창 바깥 영역 클릭 닫기 UI 구현
* `e.preventDefault()`를 통한 브라우저 기본 동작(링크 이동, 폼 제출 및 페이지 새로고침) 방지 처리 학습
* `input` / `keydown` 이벤트를 조합한 글자 수 실시간 감지 및 엔터키 입력 데이터 처리
* 폼 제출(`submit`) 시점의 클라이언트 사이드 데이터 유효성 검증(Validation) 및 예외 처리 흐름 구현

## 0. 이벤트가 뭔가

* **한 줄 비유**: 이벤트는 **초인종**임. 누가 누르면(클릭, 키 입력 등) 미리 정해둔 사람(함수)이 나가서 문을 열어줌.
* **이벤트 리스너(listener)**: "이 요소에서 이 일이 생기면 이 함수를 불러줘"라고 **등록해 둔 것**. 등록한 함수를 **이벤트 핸들러**라고 부름.
* **이벤트 객체 `e`**: 핸들러가 불릴 때 자동으로 받는 **사건 보고서**. 어디를 눌렀는지(`e.target`), 무슨 키인지(`e.key`) 같은 정보가 들어 있음.

## 1. 이벤트 등록과 해제 (`addEventListener`, `removeEventListener`)

* **`요소.addEventListener("click", 함수)`**: 그 요소를 클릭하면 함수를 부르라고 등록함.
* **`요소.removeEventListener("click", 함수)`**: 등록을 취소함. 이때 **등록할 때 넘긴 것과 똑같은 함수**를 넘겨야 함.
  * 그래서 핸들러를 `countUp`처럼 **이름 있는 함수**로 만들어 둠. 익명 함수 `() => {}`를 두 번 쓰면 생김새가 같아도 서로 **다른 함수**라 해제가 안 됨.

```javascript
/**
 * 1. 이벤트 핸들러는 참조 유지를 위해 이름이 있는 함수(countUp)로 선언
 * 2. 중지 버튼 클릭 시 removeEventListener에 동일한 함수 참조를 전달하여 이벤트 해제
 */

const countButton = document.getElementById("count-button");
const countStopButton = document.getElementById("stop-count-button");
const countResult = document.getElementById("count-result");

let count = 0;

function countUp() {
    count++;
    countResult.textContent = `클릭 횟수: ${count}`;
}

// 이벤트 등록
countButton.addEventListener("click", countUp);

// 이벤트 해제
countStopButton.addEventListener("click", () => {
    countButton.removeEventListener("click", countUp);
});

```

* **따라가기**
  1. 카운트 버튼 클릭 → `countUp` 실행 → count 1 → `클릭 횟수: 1`
  2. 한 번 더 클릭 → `클릭 횟수: 2`
  3. 중지 버튼 클릭 → 카운트 버튼에서 `countUp` 등록을 취소함.
  4. 카운트 버튼을 다시 눌러도 → 불릴 함수가 없으므로 숫자가 **2에서 멈춤**.

## 2. 이벤트 위임 (Event Delegation)

* **이벤트 버블링(Bubbling)**: 자식을 클릭하면 이벤트가 **부모 → 할아버지 → … 위로 거품처럼 올라감**. 그래서 부모에 단 리스너도 자식 클릭을 알 수 있음.
* **이벤트 위임**: 이 성질을 이용해 자식 100개에 각각 리스너를 다는 대신 **부모 하나에만** 달고, "실제로 누가 눌렸는지"를 확인해서 처리하는 방법. 반 학생 한 명 한 명에게 전화하는 대신 **반장에게 한 번** 알리는 것과 같음.
  * 장점: 리스너가 하나라 가볍고, 나중에 새로 추가된 자식도 자동으로 처리됨.
* **`e.target`**: 실제로 클릭된 **가장 안쪽 요소**. 버튼 안의 아이콘을 눌렀다면 아이콘이 `e.target`임.
* **`요소.closest("선택자")`**: 자기 자신부터 시작해 **위로 올라가며** 선택자에 맞는 가장 가까운 조상을 찾음. 없으면 `null`.

```javascript
/**
 * 부모 요소(#menu-list)에만 클릭 이벤트를 등록하고, 
 * e.target.closest()를 활용해 실제 클릭된 버튼 요소를 추적
 */

const $menuList = document.getElementById("menu-list");
const $menuItems = document.querySelectorAll(".menu-item");
const $menuResult = document.getElementById("menu-result");

$menuList.addEventListener("click", (e) => {
    const $selectBtn = e.target.closest(".select-menu");
    
    // 메뉴 선택 버튼이 아닌 곳을 클릭한 경우 실행 중단
    if (!$selectBtn) return;

    const menuId = $selectBtn.dataset.menuId;
    const menuName = $selectBtn.closest(".menu-item").querySelector("span").textContent;

    // 모든 항목의 selected 클래스 일괄 제거
    $menuItems.forEach((item) => item.classList.remove("selected"));

    // 선택된 항목에 클래스 추가 및 결과 출력
    $selectBtn.closest(".menu-item").classList.add("selected");
    $menuResult.innerHTML = `메뉴 ID : ${menuId}<br>메뉴명 : ${menuName}`;
});

```

* **예시 구조**
  ```html
  <ul id="menu-list">
    <li class="menu-item"><span>김치찌개</span><button class="select-menu" data-menu-id="1">선택</button></li>
    <li class="menu-item"><span>된장찌개</span><button class="select-menu" data-menu-id="2">선택</button></li>
  </ul>
  ```
* **따라가기: 된장찌개의 "선택" 버튼 클릭**
  1. 클릭 이벤트가 버튼 → `<li>` → `<ul id="menu-list">`로 올라옴 → `ul`의 리스너 실행.
  2. `e.target`은 버튼 → `closest(".select-menu")` → 버튼 자신이 맞음 → `$selectBtn`
  3. `$selectBtn`이 있으므로 계속 진행. (`<span>` 글자를 눌렀다면 위로 올라가도 `.select-menu`가 없어 `null` → `return`으로 끝남)
  4. `dataset.menuId` → `"2"`
  5. 버튼에서 위로 `.menu-item`(`<li>`)을 찾고, 그 안의 `<span>` 글자 → `"된장찌개"`
  6. 모든 `<li>`에서 `selected`를 떼고, 이번 `<li>`에만 붙임.
  7. 결과 영역 → `메뉴 ID : 2` / `메뉴명 : 된장찌개` (`<br>`이 줄바꿈이라 `innerHTML`로 넣음)

## 3. 전파 차단과 기본 동작 막기 (`stopPropagation`, `preventDefault`)

* **`e.stopPropagation()`**: 이벤트가 **부모로 올라가는 것을 멈춤**(버블링 차단).
* **`e.preventDefault()`**: 브라우저가 원래 하려던 **기본 동작을 취소**함. 예: `<a>` 클릭 시 페이지 이동, `<form>` 제출 시 새로고침.
* **모달 문제 상황**: 모달(팝업)은 어두운 배경(`#modal-backdrop`) **안에** 들어 있음. "배경을 누르면 닫기"를 걸어두면, 모달 **안쪽**을 눌러도 이벤트가 배경까지 올라가서 모달이 닫혀버림. → 모달 안쪽 클릭에서 `stopPropagation`으로 막음.

```javascript
/**
 * - e.stopPropagation(): 모달 콘텐츠 내부 클릭 시 부모(배경)로의 이벤트 버블링 방지
 * - e.preventDefault(): a 태그 클릭 시 기본 페이지 이동 동작 방지
 */

const $openModalButton = document.getElementById("open-modal-button");
const $modalBg = document.getElementById("modal-backdrop");
const $modal = document.getElementById("modal");
const $noticeLink = document.getElementById("notice-link");
const $modalResult = document.getElementById("modal-result");

// 모달 열기
$openModalButton.addEventListener("click", () => {
    $modalBg.classList.add("open");
});

// 배경 클릭 시 모달 닫기
$modalBg.addEventListener("click", () => {
    $modalBg.classList.remove("open");
});

// 모달 내부 클릭 시 배경으로의 이벤트 버블링 차단
$modal.addEventListener("click", (e) => {
    e.stopPropagation();
});

// 링크 기본 이동 막기 및 메시지 출력
$noticeLink.addEventListener("click", (e) => {
    e.preventDefault();
    $modalResult.textContent = $modal.querySelector("p").textContent;
});

```

* **따라가기**
  * 열기 버튼 클릭 → 배경에 `open` 클래스 → CSS로 배경과 모달이 보임.
  * **배경(바깥)** 클릭 → 배경 리스너 실행 → `open` 제거 → 모달 닫힘.
  * **모달 안쪽** 클릭 → 모달 리스너가 먼저 실행 → `stopPropagation()` → 이벤트가 배경까지 올라가지 않음 → 모달 **안 닫힘**.
  * 공지 링크 클릭 → `preventDefault()`로 페이지 이동을 취소 → 대신 모달 안 `<p>`의 글자를 결과 영역에 보여줌.

## 4. 키보드 입력 처리 (`input`, `keydown`)

| 이벤트 | 언제 발생하나 |
| :--- | :--- |
| `input` | 입력칸의 **값이 바뀔 때마다** (글자 하나 칠 때마다, 지울 때마다) |
| `keydown` | **키를 누르는 순간**. `e.key`로 어떤 키인지 알 수 있음 (`"Enter"`, `"a"` 등) |

```javascript
/**
 * - input 이벤트: 텍스트 입력 시 실시간 글자 수 카운팅
 * - keydown 이벤트: Enter 키 입력 검증 및 공백 제거(trim) 후 결과 출력
 */

const $messageInput = document.getElementById("message-input");
const charLength = document.getElementById("character-count");
const typingResult = document.getElementById("typing-result");

// 실시간 글자 수 감지
$messageInput.addEventListener("input", () => {
    charLength.textContent = `현재 글자 수: ${$messageInput.value.length}`;
});

// 엔터키 입력 처리
$messageInput.addEventListener("keydown", (e) => {
    if (e.key === "Enter") {
        const trimmedValue = $messageInput.value.trim();

        if (trimmedValue === "") {
            typingResult.textContent = "입력 결과가 여기에 표시됩니다.";
        } else {
            typingResult.textContent = trimmedValue;
        }

        // 입력창 및 글자 수 초기화
        $messageInput.value = "";
        charLength.textContent = "현재 글자 수: 0";
    }
});

```

* **따라가기: `" 안녕 "`을 치고 Enter**
  1. 글자를 칠 때마다 `input` 발생 → `현재 글자 수: 1`, `2`, … 공백 포함 4글자면 `현재 글자 수: 4`
  2. Enter 누름 → `keydown` 발생 → `e.key`가 `"Enter"` → 안으로 들어감.
  3. `.trim()` → `"안녕"` → 빈 문자열이 아님 → 결과 영역에 `안녕` 표시.
  4. 입력칸을 비우고, 글자 수를 `현재 글자 수: 0`으로 되돌림.
  * 공백만 치고 Enter → `trim()` 결과가 `""` → 안내 문구 `입력 결과가 여기에 표시됩니다.`로 되돌림.
  * 다른 키(예: `a`)는 `e.key === "Enter"`가 거짓이라 `keydown` 안에서는 아무것도 안 함.

## 5. 폼 유효성 검사 (`submit`, `preventDefault`)

* **유효성 검사(Validation)**: 서버에 보내기 전에 "이름이 너무 짧지 않나?", "약관에 동의했나?"를 **미리 검사**하는 것. 시험지를 내기 전에 이름을 썼는지 확인하는 것과 같음.
* **왜 `preventDefault`가 필요한가**: `<form>`은 제출(`submit`)되면 브라우저가 **페이지를 새로고침**함. 그러면 검사 결과를 보여줄 틈도 없이 화면이 날아감 → 먼저 기본 동작을 막고 직접 검사함.
* **`document.forms.signupForm`**: `name="signupForm"`인 `<form>`을 바로 꺼내는 방법.

```javascript
/**
 * form submit 시 발생할 기본 새로고침을 e.preventDefault()로 차단 후
 * 조건별 데이터 검증(이름 길이, 비밀번호 길이, 약관 동의) 진행
 */

const $signupForm = document.forms.signupForm;
const $userName = document.getElementById("user-name");
const $userPassword = document.getElementById("user-password");
const $termsCheckbox = document.getElementById("terms");
const $signupResult = document.getElementById("signup-result");

$signupForm.addEventListener("submit", (e) => {
    e.preventDefault();

    // 1. 이름 검증 (공백 제외 2자 이상)
    if ($userName.value.trim().length < 2) {
        $signupResult.textContent = "이름은 두 글자 이상 입력해주세요.";
        return;
    }

    // 2. 비밀번호 검증 (6자 이상)
    if ($userPassword.value.length < 6) {
        $signupResult.textContent = "비밀번호는 여섯 글자 이상 입력해주세요.";
        return;
    }

    // 3. 약관 동의 검증
    if (!$termsCheckbox.checked) {
        $signupResult.textContent = "이용 약관에 동의해주세요.";
        return;
    }

    // 검증 성공
    $signupResult.textContent = "가입 성공!";
});

```

* **따라가기** (검사는 위에서부터 차례로, 하나라도 걸리면 메시지를 띄우고 `return`으로 끝냄 = 얼리 리턴)

| 입력 | 걸리는 곳 | 결과 메시지 |
| :--- | :--- | :--- |
| 이름 `"홍"` | 1번 (`1 < 2`) | 이름은 두 글자 이상 입력해주세요. |
| 이름 `"홍길동"`, 비번 `"1234"` | 2번 (`4 < 6`) | 비밀번호는 여섯 글자 이상 입력해주세요. |
| 이름·비번 OK, 약관 체크 안 함 | 3번 (`checked`가 `false`) | 이용 약관에 동의해주세요. |
| 모두 OK | 없음 | 가입 성공! |

## 느낀 점

* `removeEventListener`를 정상 작동시키기 위해서는 익명 함수가 아닌 참조 가능한 이름이 있는 함수(Named Function)를 이벤트 핸들러로 전달해야 함을 다시금 명확히 이해함
* 여러 자식 요소에 각각 이벤트를 걸지 않고 부모 요소 하나에 이벤트를 바인딩하는 **이벤트 위임** 방식과 `closest()` 메서드를 조합하면, 메모리 관리 및 동적 노드 추가 상황 대응에 매우 유용함을 체감함
* 모달 팝업 구현 시 배경 요소를 클릭해 닫는 로직에서 모달 내부 콘텐츠 박스에 `e.stopPropagation()`을 적용하여 버블링을 끊어주는 패턴의 중요성을 파악함
* `a` 태그나 `form` 태그처럼 브라우저의 기본 동작이 포함된 요소 다룰 때는 반드시 `e.preventDefault()`를 호출하여 스크립트 실행 제어권을 확보해야 함을 확인함
