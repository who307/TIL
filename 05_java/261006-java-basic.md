# Java 기본 문법 · 형변환 · 연산자 · 메소드 정리 (TIL)

## 1. 자바 기본 문법 (리터럴, 변수, 상수, 오버플로우, 형변환)

### 리터럴(Literal)과 연산 규칙

* **리터럴**: 코드에 **직접 적은 값 그 자체**. `10`, `3.14`, `'a'`, `"abc"`, `true`처럼 계산하지 않아도 이미 정해진 값임.

| 종류 | 예 | 표기 규칙 |
| :--- | :--- | :--- |
| 정수 | `10`, `-3` | 숫자만 |
| 실수 | `3.14` | 소수점 |
| 문자 | `'a'` | **작은따옴표**, 딱 한 글자 |
| 문자열 | `"abc"` | **큰따옴표**, 여러 글자 |
| 논리값 | `true`, `false` | 참/거짓 두 개뿐 |

* **정수 + 실수** → 정수가 실수로 바뀐 뒤 계산됨. `10 + 2.5` → `10.0 + 2.5` → `12.5`
* **문자 연산** → 컴퓨터 안에서 문자는 **번호**로 저장돼 있음(유니코드, 영어는 아스키코드와 같음). `'a' + 1` → `97 + 1` → `98`
* **문자열 + 무엇이든** → `+`가 "이어 붙이기"가 됨. `"나이: " + 20` → `"나이: 20"`. 왼쪽부터 계산하므로 `1 + 2 + "개"` → `3 + "개"` → `"3개"`, `"개" + 1 + 2` → `"개1" + 2` → `"개12"`

### 변수(Variable)와 이름 규칙

* **변수**: 값을 담아두는 **이름표 붙은 상자**. 자바는 상자를 만들 때 **어떤 종류의 값을 담을지(자료형)** 반드시 정해야 함. 우유는 우유팩에, 물은 물병에 담는 것과 같음.
* **기본 자료형 8가지** (값 자체를 상자에 담음)

| 분류 | 자료형 | 크기 | 담는 값 |
| :--- | :--- | :--- | :--- |
| 정수 | `byte` | 1byte | -128 ~ 127 |
| | `short` | 2byte | 약 ±3만 |
| | `int` | 4byte | 약 ±21억 (정수의 기본) |
| | `long` | 8byte | 아주 큰 정수 (값 뒤에 `L`) |
| 실수 | `float` | 4byte | 소수 (값 뒤에 `F`) |
| | `double` | 8byte | 더 정밀한 소수 (실수의 기본) |
| 문자 | `char` | 2byte | 문자 한 개 |
| 논리 | `boolean` | 1byte | `true` / `false` |

* **참조 자료형**: `String`처럼 값이 있는 **위치(주소)** 를 상자에 담는 자료형.
* **꼭 지켜야 하는 규칙**: 같은 범위 안에서 같은 이름 두 번 선언 불가, 예약어(`int`, `class` 등) 사용 불가, 대소문자 구분(`age`와 `Age`는 다른 변수), 숫자로 시작 불가.
* **관례**: 낙타 표기법(camelCase, `userName`), `boolean`은 질문 형태(`isAlive`, `hasNext`)로 지음.

### 상수(Constant)

* **상수**: 한 번 넣으면 **바꿀 수 없는** 값. 변수 앞에 `final`을 붙임. 이름은 보통 대문자와 `_`로 씀(`final int MAX_SIZE = 10;`).
* 다시 값을 넣으려 하면 **컴파일 에러**(실행하기 전 번역 단계에서 나는 에러)가 남. 원주율처럼 절대 바뀌면 안 되는 값을 실수로 바꾸지 않게 지켜줌.

### 오버플로우(Overflow)와 언더플로우(Underflow)

* **한 줄 비유**: 자동차 **주행 거리계**가 999999 다음에 000000으로 돌아가는 것과 같음.
* 정수 자료형은 상자 크기가 정해져 있어서, 최댓값을 넘으면 **최솟값으로 한 바퀴 돌아감**(오버플로우), 최솟값보다 작아지면 **최댓값으로 돌아감**(언더플로우).
  * `byte` 최댓값 127에 1을 더하면 → `-128`
  * `byte` 최솟값 -128에서 1을 빼면 → `127`
* 그래서 값이 얼마나 커질지 생각해서 자료형을 골라야 함.

### 형변환(Typecasting)

* **형변환**: 값의 자료형을 다른 자료형으로 바꾸는 것.
* **자동 형변환**: 작은 상자 → 큰 상자로 옮길 때는 넘칠 걱정이 없어서 자바가 **알아서** 바꿔줌. `int` → `long`, 정수 → 실수(`int` → `double`).
* **강제 형변환**: 큰 상자 → 작은 상자로 옮길 때는 값이 잘릴 수 있어서, 개발자가 `(자료형)`을 붙여 **"잘려도 괜찮아"라고 직접 허락**해야 함. 큰 컵의 물을 작은 컵에 부으면 넘치는 것과 같음.

## 2. 연산자 (Operators)

### 산술·비교·논리·대입 연산자

| 종류 | 연산자 | 예 → 결과 |
| :--- | :--- | :--- |
| 산술 | `+ - * / %` | `7 / 2` → `3` (정수끼리 나누면 소수점 버림), `7 % 2` → `1` (나머지) |
| 비교 | `> < >= <= == !=` | `3 > 2` → `true` (결과는 항상 `boolean`) |
| 논리 | `&&`(그리고) `\|\|`(또는) `!`(아님) | `true && false` → `false` |
| 대입 | `= += -= *= /=` | `a += 3`은 `a = a + 3`과 같음 |

* **단락 평가(Short-Circuit Evaluation)**: 앞만 보고 답이 정해지면 **뒤는 계산하지 않음**.
  * `A && B` → A가 `false`면 B를 볼 필요 없이 `false`.
  * `A || B` → A가 `true`면 B를 볼 필요 없이 `true`.
  * 그래서 `x != 0 && 10 / x > 1`처럼 쓰면 x가 0일 때 나눗셈을 아예 하지 않아 에러를 피할 수 있음.

### 증감 연산자와 삼항 연산자

* **증감 연산자**: `++`(1 증가), `--`(1 감소). 위치에 따라 **값을 쓰는 시점**이 다름.
  * **전위 `++count`**: 먼저 1 올리고 → 그 값을 씀.
  * **후위 `count++`**: 지금 값을 먼저 쓰고 → 그다음 1 올림.
  * 예: `count = 5`일 때 `int a = ++count;` → a=6, count=6 / `int b = count++;`(count가 5였다면) → b=5, count=6
* **삼항 연산자**: `조건 ? 참일 때 값 : 거짓일 때 값`. 간단한 `if-else`를 한 줄로 쓰는 방법.

## 3. 메소드(Method)와 패키지·임포트

### 메소드 정의와 호출

* **메소드**: 자주 쓰는 일을 묶어 이름을 붙인 **작업 묶음**. 자판기처럼 값을 넣으면(매개변수) 일을 하고 결과를 돌려줌(반환값).
* **모양**: `반환형 이름(매개변수) { ...; return 값; }`
  * `int add(int a, int b) { return a + b; }` → 정수 두 개를 받아 정수를 돌려줌.
  * `void`: **돌려줄 값이 없다**는 뜻. 출력만 하고 끝나는 메소드 등에 씀.
  * `return`: 값을 돌려주고 메소드를 **즉시 끝냄**.

### 인스턴스 생성과 클래스 분리

* **클래스**: 객체를 만드는 **설계도**. **인스턴스(객체)**: 설계도로 실제로 만든 **물건**.
* `new 클래스명()`으로 인스턴스를 만들고, `인스턴스.메소드()`처럼 **점(`.`)** 으로 그 물건의 기능을 씀. (`static`이 아닌 메소드는 이렇게 객체를 만들어야 쓸 수 있음)
* 계산 담당 `Calculator` 클래스를 따로 만들고, `main`에서는 그 객체를 불러 쓰기만 하면 역할이 깔끔하게 나뉨.

### 패키지(Package)와 임포트(Import)

* **패키지**: 클래스를 담는 **폴더**. 이름이 같은 클래스가 있어도 폴더가 다르면 구분할 수 있음. 보통 회사·개인 도메인을 거꾸로 써서 `com.who307.section01`처럼 지음.
* **풀 패키지 명(Fully Qualified Name)**: 폴더 경로까지 붙인 클래스의 **전체 이름**. `com.who307.section01.method.Calculator`
* **`import`**: 다른 패키지의 클래스를 매번 긴 전체 이름으로 쓰지 않고 **짧은 이름**(`Calculator`)으로 쓰게 해주는 선언. 친구를 매번 "○○초등학교 3학년 2반 김민준"이라 부르지 않고 "민준아"라고 부르는 것과 같음.

## 핵심 코드 예시

```java
// 1. 강제 형변환 및 오버플로우 예시 (section04 & section05)
int inum = 290;
byte bnum = (byte) inum; // 강제 형변환 (데이터 손실 발생)

double dnum = 8.15;
int castedInt = (int) dnum; // 8 (소수점 절삭)

// 2. 삼항 연산자 예시 (section01/operator)
int score = 85;
String result = (score >= 60) ? "합격" : "불합격";
```

* **한 줄씩 보기**
  * `byte bnum = (byte) inum;` → 290은 `byte` 범위(-128~127)를 넘음. `byte`는 숫자를 256개(0~255 한 바퀴)로만 표현할 수 있어서, 넘친 만큼 한 바퀴를 빼버림 → `290 - 256 = 34`. 그래서 `bnum`은 **34**가 됨(데이터 손실).
  * `int castedInt = (int) dnum;` → 실수를 정수로 바꾸면 소수점 아래를 **반올림하지 않고 그냥 버림** → `8.15` → `8`
  * `(score >= 60) ? "합격" : "불합격"` → `85 >= 60`이 `true` → `"합격"`

```java
// 3. 메소드 정의 및 패키지 임포트 예시 (section01/method & section02)
// Application1.java는 section02 패키지, Calculator.java는 section01.method 패키지에 있음
package com.who307.section02.packageandimport;

import com.who307.section01.method.Calculator; // 타 패키지 클래스 임포트

public class Application1 {
    public static void main(String[] args) {
        Calculator calc = new Calculator(); // 인스턴스 생성
        int sum = calc.addTwoNumbers(10, 20); // 메소드 호출 및 반환값 수신
        System.out.println("합계: " + sum);
    }
}
```

* **한 줄씩 보기**
  * `package ...;` → 이 클래스가 들어 있는 폴더(패키지) 주소. 반드시 **파일 맨 첫 줄**(주석 제외)에 써야 함.
  * `import com.who307.section01.method.Calculator;` → `Calculator`는 **다른 패키지**(`section01.method`)에 있으므로, 짧은 이름으로 쓰려면 임포트가 필요함. 같은 패키지에 있는 클래스라면 임포트 없이 바로 쓸 수 있음.
  * `Calculator calc = new Calculator();` → 계산기 설계도로 계산기 객체 하나를 만들어 `calc` 상자에 담음.
  * `calc.addTwoNumbers(10, 20)` → 계산기에게 10과 20을 주고 더하게 함 → 돌려받은 `30`을 `sum`에 담음.
  * `System.out.println("합계: " + sum);` → 문자열 + 정수라 이어 붙여짐 → `합계: 30` 출력.

## 느낀 점

* 리터럴과 기본 데이터 타입의 연산 우선순위 및 자동/강제 형변환 메커니즘을 복습하면서 자바 메모리 구조 내에서 정수 및 실수형이 어떻게 다뤄지는지 명확히 파악함
* 오버플로우와 언더플로우 현상을 확인하며 적절한 데이터 타입 선택이 시스템 안정성과 직결된다는 점을 깨달음
* 산술, 논리, 삼항 연산자의 특성과 전위/후위 증감 연산자의 시점 차이를 구분하여 조건 처리 코드를 더욱 간결하고 안전하게 작성하는 테크닉을 습득함
* 단순히 코드 블록을 나열하는 방식에서 벗어나, 기능별로 메소드를 분리하고 인스턴스화하여 호출하는 클래스 분리 설계 및 패키지 관리의 중요성을 확인함
