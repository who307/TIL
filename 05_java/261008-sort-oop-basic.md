# Java 배열 정렬 · 객체지향 기초 정리 (TIL)

## 1. 배열 정렬 알고리즘 (Sorting Algorithms)

* **정렬**: 값들을 **작은 순서(오름차순)** 나 **큰 순서(내림차순)** 로 늘어놓는 것. 키 순서대로 줄 세우기와 같음.

### 값 교환 (Swap)

* 두 칸의 값을 바꾸려면 **임시 칸(`temp`)** 이 필요함. 오른손의 사과와 왼손의 배를 바꾸려면 하나를 잠깐 책상에 내려놓아야 하는 것과 같음.
  1. `temp = a;` → a의 값을 책상에 내려놓음.
  2. `a = b;` → a 자리에 b의 값을 넣음.
  3. `b = temp;` → 책상에 둔 원래 a의 값을 b에 넣음.
* `temp` 없이 `a = b; b = a;`라고 쓰면 첫 줄에서 a의 원래 값이 사라져서 둘 다 b의 값이 됨.

### 세 가지 정렬 방법

| 정렬 | 방법 | 비유 |
| :--- | :--- | :--- |
| **버블 정렬** | **옆 칸끼리** 비교해서 큰 값을 오른쪽으로 계속 보냄. 한 바퀴 돌면 가장 큰 값이 맨 끝에 자리 잡음 | 물속 거품이 위로 올라가듯 큰 값이 뒤로 감 |
| **선택 정렬** | 남은 칸 중 **가장 작은 값을 찾아서** 맨 앞 빈자리와 **한 번** 바꿈 | 반에서 키가 제일 작은 사람을 찾아 1번 자리에 세우기 |
| **삽입 정렬** | 앞쪽은 이미 정렬됐다고 보고, 새 값을 **알맞은 위치에 끼워 넣음** | 손에 든 카드 사이에 새 카드를 끼워 넣기 |

## 2. 객체지향 프로그래밍 (OOP) 기초

* **객체지향(Object-Oriented Programming)**: 프로그램을 **물건(객체)들이 서로 일을 시키며 돌아가는 세계**로 보고 만드는 방식.

### 사용자 정의 타입 (User Defined Type)

* 회원 한 명의 정보(아이디, 이름, 나이…)를 변수 여러 개로 따로 들고 다니면 관리가 어려움.
* 그래서 **클래스**로 "회원"이라는 새 자료형(`Member`)을 직접 만들고, 그 안에 관련된 변수들을 묶음. `int`, `String`처럼 `Member`도 하나의 자료형이 됨.

### 캡슐화 (Encapsulation)

* **한 줄 비유**: 캡슐화는 **은행 금고**임. 아무나 금고(필드)에 손을 넣을 수 없고, **창구 직원(메소드)** 을 통해서만 돈을 넣고 뺄 수 있음. 직원은 "마이너스 금액은 안 돼요" 같은 검사를 해 줌.
* **`private`**: 필드를 **클래스 안에서만** 쓸 수 있게 막음. 밖에서 `member.age = -5`처럼 엉뚱한 값을 바로 넣는 것을 차단함.
* **정보 은닉**: 내부는 숨기고, 검사를 거치는 공개 메소드만 열어두는 것.

### 추상화와 객체 간 협력

* **추상화**: 현실의 물건에서 **프로그램에 필요한 특징만** 골라 클래스로 만드는 것. 자동차에서 "시동 걸기, 가속, 브레이크"만 뽑아 `Car` 클래스로 만듦(색깔 같은 건 필요 없으면 뺌).
* **협력**: `CarRacer`(운전자) 객체가 `Car` 객체의 `startUp()`, `accelerator()`, `brake()` 메소드를 **불러서** 일을 시킴. 객체끼리 메소드 호출로 **메시지를 주고받는** 것임.

### DTO (Data Transfer Object) 패턴

* **DTO**: 데이터를 **담아서 옮기는 용도**의 객체. 택배 상자처럼 내용물을 담고 전달하는 게 일임.
* **정석 구조**
  * 필드는 모두 `private`
  * 값을 꺼내는 `getter`(`getId()`), 값을 넣는 `setter`(`setId()`)를 `public`으로 만듦

### 생성자(Constructor)와 `this`

* **생성자**: `new`로 객체를 만들 때 **딱 한 번 자동으로 실행**되는 특별한 메소드. 이름이 클래스 이름과 같고 반환형이 없음. 새 물건에 **처음 값을 채워 넣는** 역할.
  * **기본 생성자**: 매개변수가 없는 생성자 → `new MemberDTO()`
  * **매개변수 있는 생성자**: 만들면서 바로 값을 넣음 → `new MemberDTO("user01", "홍길동")`
* **`this`**: "**지금 만들어지고 있는(또는 메소드를 부른) 나 자신**"을 가리킴.
  * 매개변수 이름과 필드 이름이 같으면(`id`와 `id`), 그냥 `id`라고 쓰면 **가까운 매개변수**를 가리킴(가려짐, Shadowing). 필드를 가리키려면 `this.id`라고 써야 함.

## 핵심 코드 예시

```java
// 1. 선택 정렬 및 Swap 구현 예시 (section04/sort)
int[] arr = {2, 5, 4, 1, 3};

for (int i = 0; i < arr.length - 1; i++) {
    int minIndex = i;
    for (int j = i + 1; j < arr.length; j++) {
        if (arr[j] < arr[minIndex]) {
            minIndex = j; // 최솟값 인덱스 탐색
        }
    }
    // Swap 메커니즘
    int temp = arr[i];
    arr[i] = arr[minIndex];
    arr[minIndex] = temp;
}

```

* **따라가기** (바깥 `i`는 "이번에 채울 자리", 안쪽 `j`는 "남은 칸에서 최솟값 찾기")

| 바퀴 | 남은 칸 | 찾은 최솟값 (인덱스) | 바꾼 뒤 배열 |
| :--- | :--- | :--- | :--- |
| 처음 | - | - | `[2, 5, 4, 1, 3]` |
| `i=0` | `[2, 5, 4, 1, 3]` | 1 (3번) | 0번↔3번 → `[1, 5, 4, 2, 3]` |
| `i=1` | `[5, 4, 2, 3]` | 2 (3번) | 1번↔3번 → `[1, 2, 4, 5, 3]` |
| `i=2` | `[4, 5, 3]` | 3 (4번) | 2번↔4번 → `[1, 2, 3, 5, 4]` |
| `i=3` | `[5, 4]` | 4 (4번) | 3번↔4번 → `[1, 2, 3, 4, 5]` |

* `i < arr.length - 1`인 이유: 마지막 한 칸은 남은 게 자기 하나뿐이라 비교할 필요가 없음.
* `i=0` 바퀴를 자세히 보면: `minIndex = 0`(값 2)에서 시작 → j=1(5) 더 큼 → j=2(4) 더 큼 → j=3(1) 더 작음! `minIndex = 3` → j=4(3) 1보다 큼 → 최솟값은 3번 칸의 1 → 0번 칸과 swap.

```java
// 2. DTO 구조 및 생성자 / this 활용 예시 (section03/dto & section04/constructor)
package com.who307.section03.dto;

public class MemberDTO {
    private String id;   // private 캡슐화
    private String name;

    // 기본 생성자
    public MemberDTO() {}

    // 매개변수 생성자 및 this 활용
    public MemberDTO(String id, String name) {
        this.id = id;     // 인스턴스 필드 명시
        this.name = name;
    }

    // Getter & Setter
    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }
}

```

* **한 줄씩 보기**
  * `package com.who307.section03.dto;` → 이 클래스는 `com/who307/section03/dto` 폴더에 있음.
  * `private String id;`, `private String name;` → 밖에서 직접 못 건드리는 필드 두 개.
  * `public MemberDTO() {}` → 아무 값 없이 빈 회원 객체를 만들 때 쓰는 기본 생성자.
  * `public MemberDTO(String id, String name)` → 만들면서 값을 받는 생성자.
    * `this.id = id;` → **왼쪽** `this.id`는 객체의 필드, **오른쪽** `id`는 매개변수. "받은 값을 내 필드에 넣어라."
    * `this`를 빼고 `id = id;`라고 쓰면 매개변수에 자기 자신을 넣는 의미 없는 코드가 되고, 필드는 `null` 그대로 남음.
  * `getId()` → 필드 값을 돌려줌. `setId(String id)` → 받은 값으로 필드를 바꿈.
* **사용 예**: `MemberDTO m = new MemberDTO("user01", "홍길동");` → `m.getId()` → `"user01"` → `m.setId("user02")` → `m.getId()` → `"user02"`

## 느낀 점

* 단순 일차원 배열 조작을 넘어, 대표적인 정렬 알고리즘(버블, 선택, 삽입)의 동작 원리와 인덱스 연산 패턴을 정리하며 조건/반복문 제어 능력을 다짐
* 단순히 변수와 메소드를 나열하는 방식에서 벗어나, `private` 필드와 `public` 메소드를 조합한 캡슐화의 필요성을 명확히 인지함
* DTO 패턴의 구조와 생성자(`this`) 활용법을 다져봄으로써, 데이터를 안전하고 표준화된 방식으로 객체에 담아 전달하는 객체지향적 설계의 첫걸음을 내디딤
