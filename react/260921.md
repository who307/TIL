# React & JavaScript

## TIL(Today I Learned)

* `useMemo` Hook을 활용해 연산 비용이 큰 함수의 반환값 및 객체 참조 주소를 메모이제이션(Memoization)하여 불필요한 재연산과 렌더링 측작동을 방지하는 원리를 습득
* `useCallback` Hook을 통해 리렌더링 발생 시 함수가 재생성되는 것을 막고, 자식 컴포넌트에 Props로 전달되는 함수 참조를 유지하여 이펙트 최적화를 달성
* `useRef`를 활용해 리렌더링을 일으키지 않는 컴포넌트 내부 변수를 관리하고, DOM 요소 참조(`usernameRef.current.focus()`)를 직접 다루는 방법 체득
* 접두사 `use`로 시작하는 Custom Hook을 직접 구현하여 상태 관련 공통 로직을 독립적인 함수 단위로 분리하고 재사용하는 패턴 학습
* 비동기 처리 과정에서 발생하는 콜백 지옥(Callback Hell)의 문제점을 파악하고, `Promise` 객체의 상태(Pending, Fulfilled, Rejected)와 `.then()`, `.catch()`, `.finally()` 체이닝을 활용한 해결 기법을 습득

## 핵심 내용(코드)

### `useMemo`를 통한 연산 결과 및 객체 참조 메모이제이션

```jsx
/**
 * useMemo(() => value, [deps])
 * 1. 연산값 메모이제이션: 무거운 연산의 결과를 저장하여 의존성 변수가 변경될 때만 재계산[cite: 31]
 * 2. 참조 메모이제이션: 객체/배열 등의 참조 주소를 일정하게 유지하여 useEffect 등의 불필요한 실행 방지[cite: 32]
 */

const { useState, useEffect, useMemo } = React;

function App() {
    const [hardNumber, setHardNumber] = useState(1);
    const [isKorea, setIsKorea] = useState(true);

    // 1. 연산값 재사용: hardNumber가 바뀔 때만 heavyCalculator 실행[cite: 31]
    const hardSum = useMemo(() => {
        return hardCalculator(hardNumber);
    }, [hardNumber]);[cite: 31]

    // 2. 객체 참조 주소 보존: isKorea 상태 변화 시에만 새로운 객체 생성[cite: 32]
    const location = useMemo(() => {
        return { country: isKorea ? '한국' : '외국' };
    }, [isKorea]);[cite: 32]

    useEffect(() => {
        console.log('location 참조가 변경되었습니다.');
    }, [location]); // location 참조가 보존되어 불필요하게 호출되지 않음[cite: 32]
}

```

### `useCallback`을 통한 함수 재생성 방지

```jsx
/**
 * useCallback(() => fn, [deps])
 * - 리렌더링 시 함수 객체가 매번 새로 생성되는 것을 방지[cite: 33]
 * - 자식 컴포넌트나 useEffect의 의존성 배열로 함수를 전달할 때 참조 안정성 제공[cite: 34]
 */

function Square({ genSquareStyle }) {
    const [style, setStyle] = useState({});

    useEffect(() => {
        // genSquareStyle 함수 참조가 유지되면 부모의 다른 state 변경에 반응하지 않음[cite: 34]
        setStyle(genSquareStyle());
    }, [genSquareStyle]);[cite: 34]

    return <div style={style}></div>;
}

function ParentApp() {
    const [size, setSize] = useState(200);

    // size 변경 시에만 함수 객체를 재생성[cite: 34]
    const genSquareStyle = useCallback(() => {
        return {
            backgroundColor: "orange",
            width: `${size}px`,
            height: `${size}px`
        };
    }, [size]);[cite: 34]

    return <Square genSquareStyle={genSquareStyle} />;
}

```

### `useRef` (값 유지 및 DOM 접근)

```jsx
/**
 * useRef
 * - .current 프로퍼티에 값을 저장하며, 값이 변경되어도 리렌더링을 일으키지 않음[cite: 35]
 * - 리렌더링 시에도 값이 초기화되지 않고 유지됨[cite: 35]
 * - JSX 태그의 ref 속성에 전달하여 실제 DOM 요소에 직접 접근 가능[cite: 36]
 */

function LoginComponent() {
    const usernameRef = useRef(); // DOM 요소 접근용 Ref 생성[cite: 36]
    const countRef = useRef(0);   // 렌더링을 일으키지 않는 값 관리용 Ref[cite: 35]

    useEffect(() => {
        // 마운트 후 실제 DOM 포커스 제어[cite: 36]
        usernameRef.current.focus();[cite: 36]
    }, []);

    const increaseRef = () => {
        countRef.current += 1; // 화면 갱신 없이 내부 값만 지속 증가[cite: 35]
    };

    return (
        <input type="text" ref={usernameRef} /> // Ref와 DOM 연결[cite: 36]
    );
}

```

### Custom Hook을 활용한 로직 분리 및 재사용

```jsx
/**
 * Custom Hook 작성 규칙
 * 1. 함수 이름을 'use'로 시작[cite: 37]
 * 2. 컴포넌트 내부 최상위 수준에서만 호출[cite: 37]
 * 3. 공통 상태 관리 로직을 공유하되, 각 호출별 State는 독립적으로 작동[cite: 37]
 */

function useDelayTimer(delay) {
    const [isReady, setIsReady] = useState(false);

    useEffect(() => {
        setIsReady(false);
        const timer = setTimeout(() => {
            setIsReady(true);
        }, delay);

        // 이전 타이머 정리(Cleanup)[cite: 37]
        return () => clearTimeout(timer);
    }, [delay]);[cite: 37]

    return isReady;
}

function App() {
    const isReady = useDelayTimer(3000); // 사용자 정의 훅 호출[cite: 37]
    return <h1>{isReady ? '준비 완료!' : '대기 중...'}</h1>;[cite: 37]
}

```

### 자바스크립트 비동기: Callback Hell과 `Promise`

```javascript
/**
 * Promise: 비동기 작업의 성공/실패 결과를 나타내는 객체 (Pending, Fulfilled, Rejected)[cite: 39]
 * - .then(): 작업 성공 시 호출[cite: 39]
 * - .catch(): 에러 및 Reject 발생 시 처리[cite: 39]
 * - .finally(): 성공/실패 여부와 상관없이 실행[cite: 39]
 */

function increase(number) {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            const result = number + 10;
            if (result > 30) {
                return reject(new Error('숫자가 너무 큽니다.'));[cite: 39]
            }
            resolve(result); // 성공 전달[cite: 39]
        }, 1000);
    });
}

// Promise 체이닝을 통한 중첩(콜백 지옥) 해소[cite: 38, 39]
increase(0)
    .then(number => increase(number))[cite: 39]
    .then(number => increase(number))[cite: 39]
    .catch(error => console.log(error))[cite: 39]
    .finally(() => console.log('모든 작업 완료'));[cite: 39]

```

## 느낀 점

* `useMemo`와 `useCallback` 모두 성능 최적화 도구이지만, 원시 값 연산이 무겁거나 객체/함수 참조 동일성이 필요한 특수 상황에서만 의존성 배열과 함께 명확히 사용해야 함을 숙지함
* 단순 변수는 리렌더링마다 초기화되고 `State`는 값이 바뀌면 불필요한 리렌더링을 유발할 수 있는 반면, `useRef`는 데이터 보존과 DOM 참조라는 두 가지 목적을 리렌더링 없이 깔끔히 해결해 주는 유용한 Hook임을 확인 함
* `use` 접두사를 붙인 Custom Hook으로 타이머 등 복잡한 비동기/상태 처리 로직을 추상화함으로써, 컴포넌트 코드의 복잡도를 낮추고 가독성과 재사용성을 극대화할 수 있었음
* 비동기 작업 시 중첩 콜백 구조가 가지는 가독성 저하 문제(Callback Hell)를 `Promise` 체이닝을 도입하여 명확한 순서 제어와 종합적인 예외 처리 구조(`.catch`)로 바꿀 수 있음을 직접 체감함
