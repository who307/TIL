* 클래스형 컴포넌트와 함수형 컴포넌트의 차이점 및 가독성과 생산성을 높이는 JSX 도입의 필요성 학습

## 1. React Element 만들고 화면에 그리기

* **한 줄 비유**: React Element는 **건물 설계도**, 실제 DOM은 **지어진 건물**임. React는 설계도를 먼저 만들고, 그걸 보고 화면(건물)을 지음.
* **React Element**: "h1 태그, class는 greeting, 안에 글자는 '안녕, 리액트!'"라는 정보를 담은 **평범한 자바스크립트 객체**. 아직 화면에는 없음.
* **그리는 순서**
  1. `React.createElement(태그, 속성, 내용)` → 설계도(객체) 만들기.
  2. `ReactDOM.createRoot(요소)` → HTML의 어느 칸(`<div id="root">`)에 그릴지 정하기.
  3. `root.render(설계도)` → 그 칸에 실제로 그리기.

```javascript
/**
 * React.createElement("태그명", {속성 객체}, "자식 내용")
 * - 실제 DOM 노드가 아닌 React Element(자바스크립트 객체)를 생성한다.
 * - ReactDOM.createRoot()를 통해 root 노드를 지정하고 render()로 화면에 렌더링한다.
 */

// React 엘리먼트 생성
const greeting = React.createElement("h1", { className: "greeting" }, "안녕, 리액트!");

console.log(greeting); // React 객체 구조 출력

// DOM 렌더링
const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(greeting);

```

* **한 줄씩 보기**
  * `React.createElement("h1", { className: "greeting" }, "안녕, 리액트!")` → `{ type: "h1", props: { className: "greeting", children: "안녕, 리액트!" } }` 모양의 객체가 만들어짐.
  * `console.log(greeting)` → 화면이 아니라 콘솔에 위 객체 구조가 찍힘 → "Element는 그냥 객체구나"를 확인.
  * `ReactDOM.createRoot(document.getElementById("root"))` → `<div id="root">`를 React가 관리하는 그림판으로 지정.
  * `root.render(greeting)` → 그림판에 `<h1 class="greeting">안녕, 리액트!</h1>`이 나타남.

## 2. 컴포넌트와 JSX

* **컴포넌트(Component)**: 화면을 **레고 블록**처럼 쪼갠 조각. 헤더 블록, 버튼 블록을 만들어 두고 여러 곳에서 다시 씀. 이름은 반드시 **대문자로 시작**함(`<App />`). 소문자면 HTML 태그로 착각함.
* **클래스형 vs 함수형**
  * 클래스형: `class ... extends React.Component`로 만들고 `render()` 메서드에서 화면을 돌려줌. 예전 방식.
  * 함수형: 그냥 함수가 화면을 `return`함. 지금은 주로 이 방식을 씀.
* **JSX**: 자바스크립트 안에서 **HTML처럼 생긴 문법**으로 Element를 쓰는 방법. 실행 전에 Babel이라는 번역기가 JSX를 `React.createElement(...)` 호출로 바꿔줌. 즉 **겉모습만 HTML이고 속은 createElement**임.
* **Fragment `<>...</>`**: 컴포넌트는 **딱 하나의 덩어리**만 돌려줄 수 있음. 태그 두 개를 나란히 돌려주려면 감싸야 하는데, 쓸데없는 `<div>`를 늘리지 않으려고 **보이지 않는 빈 상자**로 감쌈.

```jsx
/**
 * 컴포넌트: UI를 재사용 가능한 독립 단위로 나눈 자바스크립트 함수/클래스 (이름은 대문자로 시작)
 * Fragment(<>...</>): 여러 태그를 반환할 때 단일 부모 노드로 감싸기 위한 빈 태그
 */

// 1. 클래스형 컴포넌트 (React.Component 상속 및 render() 필수 구현)
class TitleClass extends React.Component {
    render() {
        return React.createElement("h1", { className: "classComponent" }, "클래스형 컴포넌트입니다.");
    }
}

// 2. 함수형 컴포넌트 (createElement 방식 vs JSX 방식)
function OldWay() {
    return React.createElement(
        "div", null,
        React.createElement("h1", { className: "greeting" }, "createElement 방식"),
        React.createElement("p", null, "코드가 길고 복잡해요")
    );
}

function NewWay() {
    return (
        <>
            <h1 className="greeting">JSX 방식</h1>
            <p>HTML로 보여서 훨씬 직관적이다!!</p>
        </>
    );
}

function App() {
    return (
        <>
            <OldWay />
            <hr />
            <NewWay />
        </>
    );
}

ReactDOM.createRoot(document.getElementById("root")).render(<App />);

```

* **한 줄씩 보기**
  * `TitleClass` → 클래스형. `render()`가 `<h1>`을 돌려줌.
  * `OldWay` → createElement를 겹겹이 써서 `<div>` 안에 `<h1>`과 `<p>`를 넣음. 괄호가 많아 읽기 힘듦.
  * `NewWay` → 같은 구조를 JSX로 씀. Fragment로 `<h1>`과 `<p>`를 감쌈. HTML처럼 한눈에 보임.
  * `App` → 블록 조립: `<OldWay />`, 가로줄 `<hr />`, `<NewWay />` 순서로 배치.
  * `render(<App />)` → 화면에 "createElement 방식 / 코드가 길고 복잡해요 / (가로줄) / JSX 방식 / HTML로 보여서 훨씬 직관적이다!!"가 차례로 나옴.

## 3. JSX 문법 규칙

| 규칙 | HTML | JSX | 이유 |
| :--- | :--- | :--- | :--- |
| 값 넣기 | 불가 | `{user.name}` | `{ }` 안은 자바스크립트로 계산됨 |
| class 속성 | `class` | `className` | `class`는 자바스크립트 예약어라서 |
| 이벤트 | `onclick` | `onClick={함수}` | 속성 이름은 카멜케이스 |
| 스타일 | `style="color: red"` | `style={{ color: "red" }}` | 문자열이 아니라 **객체**로 넘김 |
| 단독 태그 | `<br>` | `<br />` | 모든 태그는 반드시 닫아야 함 |
| 주석 | `<!-- -->` | `{/* */}` | `{ }` 안의 자바스크립트 주석 |

```jsx
/**
 * JSX 주요 규칙
 * 1. { } 중괄호 내부에 자바스크립트 변수 및 표현식 삽입 가능
 * 2. HTML 속성명은 카멜 케이스(camelCase) 사용 (class -> className, onclick -> onClick 등)
 * 3. 인라인 스타일은 객체 형태로 전달 (style={{ key: value }})
 * 4. 모든 태그는 단독 태그라도 반드시 닫아야 함 (<br />, <hr />)
 */

const user = {
    name: "홍길동",
    age: 20
};

function handleClick() {
    alert("버튼이 클릭되었습니다!");
}

const customStyle = {
    backgroundColor: "cornflowerblue",
    color: "white",
    padding: "10px",
    borderRadius: "5px"
};

function JsxRules() {
    return (
        <>
            {/* JSX 내부 주석 작성 방식 */}
            <h2>1. 표현식 사용</h2>
            <h3>이름: {user.name}</h3>

            <h2>2. 속성명 카멜 케이스 규칙</h2>
            <button className="my-button" onClick={handleClick}>
                클릭해보세요
            </button>

            <h2>3. 객체형 인라인 스타일</h2>
            <p style={customStyle}>
                커스텀 스타일이 적용되었습니다.
            </p>

            <h2>4. 셀프 클로징 태그 필수</h2>
            <br />
            <hr />
        </>
    );
}

ReactDOM.createRoot(document.getElementById("root")).render(<JsxRules />);

```

* **한 줄씩 보기**
  * `{user.name}` → `"홍길동"`으로 바뀌어 `이름: 홍길동`이 보임.
  * `onClick={handleClick}` → 함수를 **괄호 없이** 넘김. 클릭할 때 React가 대신 불러줌. `onClick={handleClick()}`라고 쓰면 화면을 그릴 때 바로 실행돼 버림.
  * `style={customStyle}` → 바깥 `{ }`는 "자바스크립트 값 들어감", 그 값이 스타일 객체임. CSS의 `background-color`는 객체에서 `backgroundColor`처럼 카멜케이스로 씀. → 파란 배경, 흰 글자, 둥근 모서리 문단.
  * `<br />`, `<hr />` → 닫는 `/`가 없으면 에러.

## 4. 실시간 렌더링 (Virtual DOM 맛보기)

* **Virtual DOM(가상 DOM)**: React가 메모리에 따로 들고 있는 **화면의 복사본(설계도)**. 새 설계도가 오면 이전 설계도와 **틀린 그림 찾기**를 해서, 실제로 바뀐 부분만 진짜 화면에 고침. 벽지 한 장이 찢어졌다고 집을 새로 짓지 않는 것과 같음.

```jsx
/**
 * root.render() 함수를 호출할 때마다 매개변수로 전달된 엘리먼트 트리를 비교하여 갱신한다.
 */

function Clock() {
    return (
        <>
            <h1>실시간 시계</h1>
            <h2>현재 시간: {new Date().toLocaleTimeString()}</h2>
        </>
    );
}

const root = ReactDOM.createRoot(document.getElementById("root"));

function tick() {
    root.render(<Clock />);
}

// 1초마다 tick 함수 실행하여 시계 UI 갱신
setInterval(tick, 1000);

```

* **따라가기**
  1. `setInterval(tick, 1000)` → 1000ms(1초)마다 `tick`을 부름.
  2. `tick` → `root.render(<Clock />)` → `Clock` 함수가 다시 실행되고, 그 순간의 시간이 들어간 새 설계도가 만들어짐.
  3. React가 이전 설계도와 비교 → `<h1>실시간 시계</h1>`는 같음, `<h2>`의 시간 글자만 다름.
  4. 진짜 화면에서는 **시간 글자만** 바뀜 → `현재 시간: 오후 3:00:00` → `오후 3:00:01` → …

## 5. Props와 `children`

* **Props(Properties)**: 부모 컴포넌트가 자식 컴포넌트에게 넘겨주는 **값 꾸러미**. 함수의 매개변수와 같음.
  * **읽기 전용**: 자식은 받은 props를 **바꿀 수 없음**. 선물받은 편지의 내용을 고쳐 쓰지 않는 것처럼.
  * **단방향**: 데이터는 **부모 → 자식** 한 방향으로만 흐름.
* **넘기는 법**: `<Greeting name={name1} favoriteNumber={5}>` → 자식은 `{ name, favoriteNumber }` 객체로 받음.
* **기본값**: 매개변수 구조 분해에서 `name = "기본이름"`처럼 정해두면, 부모가 안 넘겼을 때 그 값을 씀.
* **`children`**: 태그를 열고 닫은 **사이에 넣은 내용**이 자동으로 `children`이라는 이름의 prop으로 들어감.

```jsx
/**
 * Props (Properties)
 * - 부모 컴포넌트에서 자식 컴포넌트로 전달되는 읽기 전용(Read-only) 데이터
 * - 단방향 데이터 흐름 (부모 -> 자식)
 * - 구조 분해 할당 및 파라미터 기본값 지정 가능
 * - 컴포넌트 태그 사이의 요소는 props.children으로 전달됨
 */

function Greeting({ name = "기본이름", favoriteNumber = "1", children }) {
    return (
        <>
            <h1>안녕하세요, {name}님!</h1>
            <h2>제가 좋아하는 숫자는 {favoriteNumber}</h2>
            <strong>전달된 자식 요소(children): {children}</strong>
        </>
    );
}

function App() {
    const name1 = "홍길동";
    const name2 = "유관순";

    return (
        <>
            {/* 태그 사이에 전달한 콘텐츠가 children 속성으로 전달됨 */}
            <Greeting name={name1} favoriteNumber={5}>
                props 공부 중!
            </Greeting>
            <Greeting name={name2} favoriteNumber={7}>
                <div>여러 줄도 가능</div>
                <div>React</div>
            </Greeting>
            {/* Props 미전달 시 설정한 기본값이 출력됨 */}
            <Greeting />
        </>
    );
}

const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(<App />);

```

* **따라가기 (Greeting이 3번 그려짐)**

| 호출 | `name` | `favoriteNumber` | `children` | 화면 |
| :--- | :--- | :--- | :--- | :--- |
| 1번째 | 홍길동 | 5 | `"props 공부 중!"` | 안녕하세요, 홍길동님! / 제가 좋아하는 숫자는 5 / 전달된 자식 요소(children): props 공부 중! |
| 2번째 | 유관순 | 7 | `<div>` 두 개 | 안녕하세요, 유관순님! / … 7 / 여러 줄도 가능, React |
| 3번째 | (안 넘김 → 기본값) 기본이름 | (기본값) 1 | 없음 | 안녕하세요, 기본이름님! / … 1 / 전달된 자식 요소(children): |

* `favoriteNumber={5}`처럼 `{ }`로 넘기면 **숫자** 5, `favoriteNumber="5"`로 넘기면 **문자열** "5"가 됨.

## 느낀 점

* 기존 `React.createElement` 방식의 복잡했던 중첩 구조를 JSX 문법을 통해 HTML과 유사하고 직관적인 선언형 UI 코드로 작성할 수 있게 되어 생산성과 가독성이 크게 향상됨을 확인함
* HTML 문법과 유사해 보이지만 `className`, `onClick`과 같은 속성명 표기법 차이와 인라인 스타일을 객체 형태로 넘겨야 하는 등 JSX 특유의 자바스크립트 기반 제약 규칙을 명확히 숙지함
* React의 핵심 구조인 Props를 사용하여 부모-자식 간 데이터 흐름을 형성하고, ES6 구조 분해 할당과 `children` 속성을 활용해 유연하고 재사용성 높은 컴포넌트 구조를 설계하는 패턴을 파악함
