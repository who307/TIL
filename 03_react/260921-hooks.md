# React useMemo · useCallback · useRef · 커스텀 훅 정리 (TIL)

## TIL(Today I Learned)

* `useMemo` Hook을 활용해 연산 비용이 큰 함수의 반환값 및 객체 참조 주소를 메모이제이션(Memoization)하여 불필요한 재연산과 렌더링 오작동을 방지하는 원리를 습득
* `useCallback` Hook을 통해 리렌더링 발생 시 함수가 재생성되는 것을 막고, 자식 컴포넌트에 Props로 전달되는 함수 참조를 유지하여 이펙트 최적화를 달성
* `useRef`를 활용해 리렌더링을 일으키지 않는 컴포넌트 내부 변수를 관리하고, DOM 요소 참조(`usernameRef.current.focus()`)를 직접 다루는 방법 체득
* 접두사 `use`로 시작하는 Custom Hook을 직접 구현하여 상태 관련 공통 로직을 독립적인 함수 단위로 분리하고 재사용하는 패턴 학습
* 비동기 처리 과정에서 발생하는 콜백 지옥(Callback Hell)의 문제점을 파악하고, `Promise` 객체의 상태(Pending, Fulfilled, Rejected)와 `.then()`, `.catch()`, `.finally()` 체이닝을 활용한 해결 기법을 습득

## 0. 먼저 알아둘 것: 다시 그릴 때마다 모든 게 새로 만들어짐

* 컴포넌트는 state가 바뀔 때마다 **함수 전체가 처음부터 다시 실행**됨. 그래서 함수 안의 계산, 객체 `{}`, 함수 `() => {}`도 **매번 새로 만들어짐**.
* 문제 1: 무거운 계산을 상관없는 state가 바뀔 때도 매번 다시 함 → 느려짐.
* 문제 2: 객체·함수는 내용이 같아도 새로 만들면 **다른 것**으로 취급됨(`{} === {}`는 `false`). 그래서 `useEffect`의 의존성 배열에 넣으면 "바뀌었다!"고 착각해 매번 실행됨.
* **메모이제이션(Memoization)**: 한 번 계산한 결과를 **메모해 두고**, 재료가 바뀌지 않았으면 메모를 그대로 꺼내 쓰는 기법. 오늘 배운 `useMemo`, `useCallback`이 이 역할을 함.

## 1. `useMemo`: 계산 결과와 객체를 기억하기

* **한 줄 비유**: 어려운 수학 문제를 풀고 **답을 메모지에 적어두는 것**. 문제(재료)가 바뀌지 않으면 다시 풀지 않고 메모지를 봄.
* **모양**: `const 결과 = useMemo(() => 계산, [재료들]);`
  * 처음 → 계산하고 결과를 기억.
  * 다시 그릴 때 → `[재료들]` 중 하나라도 바뀌었으면 다시 계산, 아니면 기억해 둔 결과를 그대로 돌려줌.

```jsx
/**
 * useMemo(() => value, [deps])
 * 1. 연산값 메모이제이션: 무거운 연산의 결과를 저장하여 의존성 변수가 변경될 때만 재계산
 * 2. 참조 메모이제이션: 객체/배열 등의 참조 주소를 일정하게 유지하여 useEffect 등의 불필요한 실행 방지
 */

const { useState, useEffect, useMemo } = React;

function App() {
    const [hardNumber, setHardNumber] = useState(1);
    const [isKorea, setIsKorea] = useState(true);

    // 1. 연산값 재사용: hardNumber가 바뀔 때만 hardCalculator 실행
    const hardSum = useMemo(() => {
        return hardCalculator(hardNumber);
    }, [hardNumber]);

    // 2. 객체 참조 주소 보존: isKorea 상태 변화 시에만 새로운 객체 생성
    const location = useMemo(() => {
        return { country: isKorea ? '한국' : '외국' };
    }, [isKorea]);

    useEffect(() => {
        console.log('location 참조가 변경되었습니다.');
    }, [location]); // location 참조가 보존되어 불필요하게 호출되지 않음
}

```

* **따라가기**
  1. 처음 → `hardCalculator(1)` 계산(오래 걸린다고 가정), `location = { country: '한국' }` 생성 → 이펙트 실행 → `location 참조가 변경되었습니다.`
  2. `hardNumber`가 2로 바뀜 → `hardSum`만 다시 계산. `isKorea`는 그대로라 `location`은 **기억해 둔 같은 객체** → 이펙트 실행 안 됨.
  3. `isKorea`가 `false`로 바뀜 → 무거운 계산은 건너뜀(재료 `hardNumber` 그대로). `location`은 새 객체 `{ country: '외국' }` → 이펙트 실행.
  * `useMemo`가 없었다면 2번에서도 `location`이 새 객체로 만들어져 이펙트가 쓸데없이 실행됐을 것임.

## 2. `useCallback`: 함수를 기억하기

* **한 줄 비유**: `useMemo`가 "답"을 기억한다면, `useCallback`은 **"풀이 방법(함수)" 자체**를 기억함.
* **모양**: `const 함수 = useCallback(() => {...}, [재료들]);` → 재료가 바뀔 때만 새 함수를 만들고, 아니면 이전 함수를 그대로 씀.
* **언제 쓰나**: 함수를 자식에게 props로 넘기거나 `useEffect`의 의존성 배열에 넣을 때. 매번 새 함수면 받는 쪽이 "바뀌었다"고 착각하기 때문임.

```jsx
/**
 * useCallback(() => fn, [deps])
 * - 리렌더링 시 함수 객체가 매번 새로 생성되는 것을 방지
 * - 자식 컴포넌트나 useEffect의 의존성 배열로 함수를 전달할 때 참조 안정성 제공
 */

function Square({ genSquareStyle }) {
    const [style, setStyle] = useState({});

    useEffect(() => {
        // genSquareStyle 함수 참조가 유지되면 부모의 다른 state 변경에 반응하지 않음
        setStyle(genSquareStyle());
    }, [genSquareStyle]);

    return <div style={style}></div>;
}

function ParentApp() {
    const [size, setSize] = useState(200);

    // size 변경 시에만 함수 객체를 재생성
    const genSquareStyle = useCallback(() => {
        return {
            backgroundColor: "orange",
            width: `${size}px`,
            height: `${size}px`
        };
    }, [size]);

    return <Square genSquareStyle={genSquareStyle} />;
}

```

* **따라가기**
  1. 처음 → `size`는 200 → `genSquareStyle` 함수 생성 → `Square`에 전달.
  2. `Square`의 이펙트 → `genSquareStyle()` 호출 → `{ 주황색, 200px, 200px }` → 200px 주황 정사각형이 그려짐.
  3. 부모의 **다른 state**가 바뀌어 다시 그림 → `size`가 그대로라 **같은 함수**를 넘김 → `Square`의 이펙트는 다시 실행되지 않음.
  4. `size`가 300으로 바뀜 → 새 함수 생성 → `Square`의 이펙트가 "함수가 바뀌었네" 하고 실행 → 300px 정사각형으로 바뀜.

## 3. `useRef`: 다시 그리지 않는 기억 상자 + DOM 손잡이

* **한 줄 비유**: `useRef`는 컴포넌트의 **비밀 주머니**임. 안에 뭘 넣고 바꿔도 화면은 다시 그려지지 않고, 다시 그려져도 주머니 속 물건은 그대로 남아 있음.
* **모양**: `const ref = useRef(처음값);` → 값은 `ref.current`에 들어 있음.
* **쓰임 2가지**

| 용도 | 방법 | 예 |
| :--- | :--- | :--- |
| 화면과 상관없는 값 기억 | `ref.current += 1` | 클릭 횟수를 세되 화면에는 안 보여줄 때 |
| 실제 DOM 요소 잡기 | `<input ref={ref} />` | 입력칸에 커서 놓기(`focus`) |

* **세 가지 비교**: 일반 변수는 다시 그릴 때 **초기화됨**, state는 바꾸면 **다시 그림**, ref는 **둘 다 아님**(유지되고 다시 그리지도 않음).

```jsx
/**
 * useRef
 * - .current 프로퍼티에 값을 저장하며, 값이 변경되어도 리렌더링을 일으키지 않음
 * - 리렌더링 시에도 값이 초기화되지 않고 유지됨
 * - JSX 태그의 ref 속성에 전달하여 실제 DOM 요소에 직접 접근 가능
 */

function LoginComponent() {
    const usernameRef = useRef(); // DOM 요소 접근용 Ref 생성
    const countRef = useRef(0);   // 렌더링을 일으키지 않는 값 관리용 Ref

    useEffect(() => {
        // 마운트 후 실제 DOM 포커스 제어
        usernameRef.current.focus();
    }, []);

    const increaseRef = () => {
        countRef.current += 1; // 화면 갱신 없이 내부 값만 지속 증가
    };

    return (
        <input type="text" ref={usernameRef} /> // Ref와 DOM 연결
    );
}

```

* **따라가기**
  1. 그리기 → `<input ref={usernameRef} />` → React가 실제 입력칸 요소를 `usernameRef.current`에 넣어줌.
  2. 화면에 나타난 뒤(빈 배열이라 한 번만) 이펙트 실행 → `usernameRef.current.focus()` → 페이지가 열리자마자 입력칸에 **커서가 깜빡임**.
  3. `increaseRef`를 부르면 `countRef.current`가 1, 2, 3… 늘어나지만 화면은 다시 그려지지 않음.

## 4. 커스텀 훅 (Custom Hook)

* **한 줄 비유**: 자주 쓰는 Hook 조합을 **나만의 도구 상자**로 묶어두는 것. 여러 컴포넌트에서 같은 로직을 복사하지 않고 꺼내 씀.
* **규칙**
  1. 이름은 반드시 **`use`로 시작**함. React가 Hook인지 알아보는 표시임.
  2. 컴포넌트(또는 다른 Hook)의 **맨 위에서만** 부름. `if`나 반복문 안에서 부르면 안 됨.
  3. 여러 컴포넌트가 같은 커스텀 훅을 써도 **state는 각자 따로** 가짐. 로직만 공유하는 것임.

```jsx
/**
 * Custom Hook 작성 규칙
 * 1. 함수 이름을 'use'로 시작
 * 2. 컴포넌트 내부 최상위 수준에서만 호출
 * 3. 공통 상태 관리 로직을 공유하되, 각 호출별 State는 독립적으로 작동
 */

function useDelayTimer(delay) {
    const [isReady, setIsReady] = useState(false);

    useEffect(() => {
        setIsReady(false);
        const timer = setTimeout(() => {
            setIsReady(true);
        }, delay);

        // 이전 타이머 정리(Cleanup)
        return () => clearTimeout(timer);
    }, [delay]);

    return isReady;
}

function App() {
    const isReady = useDelayTimer(3000); // 사용자 정의 훅 호출
    return <h1>{isReady ? '준비 완료!' : '대기 중...'}</h1>;
}

```

* **따라가기**
  1. `App`이 `useDelayTimer(3000)` 호출 → 훅 안의 `isReady`는 `false` → 화면에 `대기 중...`
  2. 화면에 나타난 뒤 이펙트 → 3000ms(3초) 뒤에 `setIsReady(true)`를 하도록 타이머 예약.
  3. 3초 후 → `isReady`가 `true` → `App`이 다시 그려짐 → `준비 완료!`
  4. `delay` 값이 바뀌거나 컴포넌트가 사라지면 → 클린업으로 이전 타이머를 취소함 → 엉뚱한 때에 `true`가 되는 것을 막음.

## 5. 콜백 지옥과 `Promise`

* **비동기(Asynchronous)**: 시간이 걸리는 일(타이머, 서버 요청)을 맡겨두고 **기다리지 않고** 다음 코드를 먼저 실행하는 방식. 세탁기를 돌려놓고 그동안 숙제하는 것과 같음.
* **콜백 지옥(Callback Hell)**: "A 끝나면 B, B 끝나면 C…"를 콜백 안에 콜백을 넣어 쓰다 보면 코드가 **오른쪽으로 계속 깊어지는** 문제. 읽기도 고치기도 어려움.
* **Promise**: "나중에 결과를 꼭 알려줄게"라는 **약속 영수증**. 상태가 3가지임.

| 상태 | 뜻 | 바뀌는 계기 |
| :--- | :--- | :--- |
| Pending (대기) | 아직 작업 중 | 처음 상태 |
| Fulfilled (이행) | 성공 | `resolve(값)` 호출 |
| Rejected (거부) | 실패 | `reject(에러)` 호출 |

* **처리 메서드**: `.then(성공 시)`, `.catch(실패 시)`, `.finally(성공이든 실패든 마지막에)`. `.then`이 돌려준 값(또는 Promise)이 다음 `.then`으로 넘어가서 **위에서 아래로 줄줄이** 이어 쓸 수 있음(체이닝).

```javascript
/**
 * Promise: 비동기 작업의 성공/실패 결과를 나타내는 객체 (Pending, Fulfilled, Rejected)
 * - .then(): 작업 성공 시 호출
 * - .catch(): 에러 및 Reject 발생 시 처리
 * - .finally(): 성공/실패 여부와 상관없이 실행
 */

function increase(number) {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            const result = number + 10;
            if (result > 30) {
                return reject(new Error('숫자가 너무 큽니다.'));
            }
            resolve(result); // 성공 전달
        }, 1000);
    });
}

// Promise 체이닝을 통한 중첩(콜백 지옥) 해소
increase(0)
    .then(number => increase(number))
    .then(number => increase(number))
    .catch(error => console.log(error))
    .finally(() => console.log('모든 작업 완료'));

```

* **따라가기** (`increase`는 1초 뒤에 +10한 값을 약속함. 30을 넘으면 실패)
  1. `increase(0)` → 1초 뒤 `10 > 30`? 아니오 → `resolve(10)`
  2. 첫 번째 `.then` → `increase(10)` → 1초 뒤 `resolve(20)`
  3. 두 번째 `.then` → `increase(20)` → 1초 뒤 `30 > 30`? 아니오 → `resolve(30)`
  4. 실패가 없었으므로 `.catch`는 건너뜀.
  5. `.finally` → `모든 작업 완료` 출력 (시작부터 약 3초 뒤).
  * `.then`을 하나 더 붙였다면 `increase(30)` → `40 > 30` → `reject` → 남은 `.then`은 건너뛰고 `.catch`에서 `Error: 숫자가 너무 큽니다.` 출력 → 그다음 `.finally` 실행.

## 느낀 점

* `useMemo`와 `useCallback` 모두 성능 최적화 도구이지만, 원시 값 연산이 무겁거나 객체/함수 참조 동일성이 필요한 특수 상황에서만 의존성 배열과 함께 명확히 사용해야 함을 숙지함
* 단순 변수는 리렌더링마다 초기화되고 `State`는 값이 바뀌면 불필요한 리렌더링을 유발할 수 있는 반면, `useRef`는 데이터 보존과 DOM 참조라는 두 가지 목적을 리렌더링 없이 깔끔히 해결해 주는 유용한 Hook임을 확인함
* `use` 접두사를 붙인 Custom Hook으로 타이머 등 복잡한 비동기/상태 처리 로직을 추상화함으로써, 컴포넌트 코드의 복잡도를 낮추고 가독성과 재사용성을 극대화할 수 있었음
* 비동기 작업 시 중첩 콜백 구조가 가지는 가독성 저하 문제(Callback Hell)를 `Promise` 체이닝을 도입하여 명확한 순서 제어와 종합적인 예외 처리 구조(`.catch`)로 바꿀 수 있음을 직접 체감함
