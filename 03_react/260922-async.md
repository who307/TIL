## 1. `async/await`와 `try...catch`

* **한 줄 비유**: `await`는 **"택배 올 때까지 현관에서 기다려"** 라는 말임. 택배(Promise 결과)가 도착하면 그 물건을 받아서 다음 줄로 넘어감.
* **규칙**
  * `await`는 **`async`가 붙은 함수 안에서만** 쓸 수 있음.
  * `await Promise` → Promise가 성공하면 **결과 값**이 나옴. 실패하면 그 자리에서 **에러가 던져짐**.
  * 던져진 에러는 `try { } catch (error) { }`로 잡음. `.then().catch()` 체이닝을 위에서 아래로 읽히는 평범한 코드처럼 바꾼 것임.
* **기다리는 동안 다른 일은?**: `run` 함수 안에서만 멈춰 있고, 브라우저의 다른 작업(클릭 처리 등)은 계속 돌아감.

```javascript
/**
 * async/await
 * - async 함수 내에서 await 키워드를 사용해 Promise가 완료될 때까지 대기
 * - 비동기 에러는 try...catch 블록을 통해 동기식 에러 처리와 동일한 구조로 캡처
 */

function increase(number) {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            const result = number + 10;
            if (result > 30) return reject(new Error('숫자가 너무 큽니다.'));
            resolve(result);
        }, 1000);
    });
}

async function run() {
    try {
        let result = await increase(0);
        console.log(result);
        result = await increase(result);
        console.log(result);
    } catch (error) {
        // Promise reject 발생 시 catch 블록으로 진입
        console.error(error);
    }
}

```

* **따라가기: `run()` 실행**
  1. `await increase(0)` → 1초 기다림 → `resolve(10)` → `result = 10` → `10` 출력.
  2. `await increase(10)` → 1초 기다림 → `resolve(20)` → `result = 20` → `20` 출력.
  3. 실패가 없으므로 `catch`는 실행되지 않음.
  * 만약 중간에 `increase(30)`처럼 실패하는 호출이 있었다면 → `reject` → 그 줄에서 에러가 던져짐 → 아래 줄은 건너뛰고 `catch`로 점프 → `Error: 숫자가 너무 큽니다.` 출력.

## 2. `fetch` vs `axios`

* **API**: 다른 서버에 "데이터 좀 줘"라고 요청하고 답을 받는 창구. 식당 주문 창구와 같음.
* **HTTP 상태 코드**: 서버가 답과 함께 붙여주는 **결과 번호**. 2xx는 성공, 4xx는 요청한 쪽 잘못(404 = 없음), 5xx는 서버 잘못.
* **JSON**: 서버가 데이터를 보낼 때 쓰는 글자 형식. `{"name":"Leanne"}`처럼 생겼고, 자바스크립트 객체로 바꿔야 쓸 수 있음.

| 구분 | `fetch` | `axios` |
| :--- | :--- | :--- |
| 설치 | 브라우저에 내장 | 외부 라이브러리 설치 필요 |
| JSON 변환 | `await response.json()`을 **직접** 해야 함 | 자동. `response.data`에 바로 들어 있음 |
| 404, 500 응답 | **실패로 치지 않음** → `response.ok`를 직접 확인해야 함 | 자동으로 실패(reject) 처리 → 바로 `catch`로 감 |
| 실패로 치는 경우 | 인터넷이 끊기는 등 요청 자체가 안 될 때만 | 네트워크 오류 + 4xx/5xx |

```javascript
/**
 * fetch vs Axios
 * 1. fetch: 브라우저 내장. response.ok 확인 및 response.json() 파싱 단계가 필수적임
 * 2. Axios: 외부 라이브러리. JSON 파싱이 자동화(response.data)되며, 4xx/5xx HTTP 에러를 자동으로 reject함
 */

const API_URL = 'https://jsonplaceholder.typicode.com/users/1';

// fetch API 활용 방식
async function callApiWithFetch() {
    try {
        const response = await fetch(API_URL);
        if (!response.ok) throw new Error('HTTP error'); // ok 여부 직접 확인 필요
        const data = await response.json();              // json 변환 필요
        console.log(data);
    } catch (error) {
        console.error('fetch 에러:', error);
    }
}

// Axios 활용 방식
async function callApiWithAxios() {
    try {
        const response = await axios.get(API_URL);
        const data = response.data; // 자동 파싱된 데이터 바로 사용
        console.log(data);
    } catch (error) {
        // 4xx, 5xx 에러도 catch 블록에서 바로 포착
        console.error('axios 에러:', error);
    }
}

```

* **따라가기: `callApiWithFetch()`**
  1. `await fetch(API_URL)` → 서버에 1번 사용자 정보를 요청하고 응답 상자(`response`)를 받음.
  2. `response.ok` → 상태 코드가 200번대면 `true`. 아니면 직접 `throw`해서 `catch`로 보냄.
  3. `await response.json()` → 응답 본문(JSON 글자)을 객체로 바꿈. 이것도 시간이 걸려서 `await`가 필요함.
  4. `console.log(data)` → `{ id: 1, name: "Leanne Graham", ... }` 같은 사용자 객체 출력.
* **따라가기: `callApiWithAxios()`**
  1. `await axios.get(API_URL)` → 요청 + JSON 변환까지 한 번에.
  2. `response.data` → 바로 사용자 객체.
  3. 서버가 404를 돌려줬다면 → axios가 알아서 실패 처리 → `catch`에서 `axios 에러:` 출력.

## 3. `useEffect` 안에서 데이터 가져오기 (loading / error / data)

* **왜 `useEffect` 안에서?**: 컴포넌트 함수 본문에서 바로 요청하면 다시 그릴 때마다 요청이 또 나감 → `useEffect(..., [])`로 **처음 한 번만** 요청함.
* **state 3개로 화면 상태 나누기**
  * `loading`: 아직 기다리는 중인가? → "로딩 중..." 표시
  * `error`: 실패했나? → 오류 메시지 표시
  * `users`(data): 성공했나? → 목록 표시

```jsx
/**
 * API 통신 시 로딩 및 에러 상태 처리 패턴
 * - useEffect 내부에서 비동기 함수를 선언 및 호출
 * - finally 블록을 활용해 성공/실패와 관계없이 로딩 상태 해제
 */

const { useState, useEffect } = React;

function UserList() {
    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        fetch('https://jsonplaceholder.typicode.com/users')
            .then(res => {
                if (!res.ok) throw new Error('네트워크 응답 오류');
                return res.json();
            })
            .then(data => setUsers(data))
            .catch(err => setError(err))
            .finally(() => setLoading(false)); // 성공/실패 여부 관계없이 로딩 종료
    }, []);

    if (loading) return <p>로딩 중...</p>;
    if (error) return <p>오류 발생: {error.message}</p>;

    return (
        <ul>
            {users.map(user => (
                <li key={user.id}>{user.name} ({user.company?.name})</li> // 옵셔널 체이닝 사용
            ))}
        </ul>
    );
}

```

* **따라가기 (성공하는 경우)**
  1. 처음 그리기 → `loading`이 `true` → `로딩 중...`만 보임.
  2. 그린 뒤 이펙트 → 사용자 목록 요청 시작.
  3. 응답 도착 → `res.ok` 확인 → `res.json()`으로 변환 → `setUsers(10명 배열)`
  4. `.finally` → `setLoading(false)`
  5. 다시 그리기 → `loading`은 `false`, `error`는 `null` → 목록 표시 → `Leanne Graham (Romaguera-Crona)` 같은 줄 10개.
  * `user.company?.name` → 회사 정보가 없는 사용자가 있어도 에러 없이 `undefined`로 넘어감.
* **실패하는 경우**: 3번에서 `throw` → `.catch` → `setError(에러)` → `.finally`로 로딩 종료 → 다시 그리면 `오류 발생: 네트워크 응답 오류`

## 4. `Promise.all`로 여러 요청을 한꺼번에

* **상황**: 포켓몬 목록 API는 이름과 **상세 정보 주소(url)** 만 줌. 사진을 보려면 포켓몬마다 상세 주소로 **또 요청**해야 함 (20마리면 20번).
* **하나씩 기다리면**: 1마리 요청 → 기다림 → 2마리 요청 → 기다림 … 20번 기다림. 줄 서서 한 명씩 계산하는 것과 같음.
* **`Promise.all([약속들])`**: 요청 20개를 **동시에** 보내 놓고, **전부 끝날 때까지** 한 번만 기다림. 계산대 20개를 한꺼번에 여는 것과 같음. 결과는 넣은 순서대로 배열로 나옴. 하나라도 실패하면 전체가 실패함.

```jsx
/**
 * 목록 API 수신 후 각 상세 URL에 대한 추가 API 병렬 요청
 * - Array.prototype.map을 활용해 Promise 객체 배열을 생성
 * - Promise.all을 통해 모든 요청이 완료될 때까지 한 번에 대기 후 상태 업데이트
 */

function PokemonList() {
    const [pokemons, setPokemons] = useState([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
        const fetchPokemons = async () => {
            try {
                const res = await fetch('https://pokeapi.co/api/v2/pokemon');
                const data = await res.json();

                // 상세 URL 요청을 위한 Promise 배열 생성
                const detailPromises = data.results.map(async (poke) => {
                    const detailRes = await fetch(poke.url);
                    if (!detailRes.ok) throw new Error('포켓몬 정보 불러오기 실패');
                    return detailRes.json();
                });

                // 병렬 비동기 요청 전체 수집
                const results = await Promise.all(detailPromises);
                setPokemons(results);
            } catch (err) {
                console.error(err);
            } finally {
                setLoading(false);
            }
        };

        fetchPokemons();
    }, []);

    if (loading) return <p>불러오는 중...</p>;

    return (
        <div>
            {pokemons.map(pokemon => (
                <div key={pokemon.id}>
                    <img src={pokemon.sprites.front_default} alt={pokemon.name} />
                    <h3>{pokemon.name}</h3>
                </div>
            ))}
        </div>
    );
}

```

* **따라가기**
  1. `useEffect`의 함수 자체에는 `async`를 붙일 수 없어서(클린업 자리에 Promise가 들어가 버림), 안에 `async` 함수 `fetchPokemons`를 만들고 바로 부름.
  2. 목록 요청 → `data.results` = `[{ name: "bulbasaur", url: ".../1/" }, ...]` 20개.
  3. `map(async (poke) => ...)` → 칸마다 상세 요청을 **시작**하고, 각각의 Promise를 담은 배열 20칸을 만듦. 이 시점에 20개 요청이 이미 동시에 출발함.
  4. `await Promise.all(detailPromises)` → 20개가 모두 끝나기를 한 번에 기다림 → 상세 정보 20개 배열.
  5. `setPokemons(results)` → `finally`에서 로딩 종료 → 다시 그리면 사진(`sprites.front_default`)과 이름이 20개 보임.

## 5. 콜백 방식 API를 Promise로 감싸기

* `navigator.geolocation.getCurrentPosition(성공콜백, 실패콜백)`처럼 **옛날식 콜백 API**는 `await`를 바로 쓸 수 없음.
* `new Promise((resolve, reject) => { ... })` 안에서 그 API를 부르고, 성공 콜백에서 `resolve`, 실패 콜백에서 `reject`를 부르도록 연결하면 → `await`로 기다릴 수 있는 Promise가 됨. 위 `increase` 함수가 `setTimeout`(콜백 방식)을 Promise로 감싼 것과 같은 원리임.

## 느낀 점

* `.then()` 체이닝 방식보다 `async/await`와 `try...catch` 구문을 조합하는 방식이 코드의 가독성을 대폭 향상시켜 주며, 에러 발생 시 어느 지점에서 예외가 던져졌는지 명확히 파악할 수 있음을 깨달음
* `fetch` API는 HTTP 404, 500 에러에서도 `reject`되지 않으므로 `response.ok`를 별도로 검증해야 하는 반면, `axios`는 HTTP 상태 코드에 따른 예외 처리를 자동으로 제공해 주어 실무에서 생산성을 더욱 높여줄 수 있음을 이해함
* 목록 API 수신 후 각 항목별 상세 정보를 조회해야 하는 케이스에서, 반복문 내부의 직렬 `await` 대신 `map`과 `Promise.all`을 연결하는 방식을 적용하여 네트워크 병목을 획기적으로 줄이는 비동기 최적화 기법을 습득함
